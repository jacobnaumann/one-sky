## 06:10 UTC: First working build — globe, backend, app wired together
- **What:** Globe (`src/globe/`: custom day/night shader from real sun position, city lights, clouds, atmosphere, stars, people/echo/lantern/gaze points, wave arcs, threads, 24-part ring, bloom). Supabase project `evktxfawnualbbmoujip` with schema, RLS, rate-limited RPCs, pg_cron prune, 6 seeded welcome lanterns. Pure lib (`src/lib/`: sun, geo, tz table of 418 places, time, questions, moderation). Audio engine (`src/audio/engine.ts`). Network layer (`src/net/sky.ts`), UI (`index.html`, `src/styles.css`, `src/ui/`), orchestration (`src/main.ts`).
- **Why:** Core of the plan.
- **Decisions:** Backend, lib and audio were each built by a parallel helper agent to a written interface; I built the globe, UI and wiring. Column-level grants hide uids (clients must list columns, never `select *`). Hidden lanterns are announced by a `lantern_hidden` broadcast which the client confirms against the DB because public broadcasts can be spoofed. Place names sent by clients are screened server-side like lantern text. `world_totals` single-row table keeps thread/km totals cheap. Presence starts only after the visitor presses "Step into the sky".
- **Verified:** `npx tsc --noEmit` clean. `npx vitest run` 124/124. `node tests/db/rls.test.mjs` 83/83 against the live project (run by the backend helper). Sound has NOT been listened to by anyone. Two-client behaviour not yet tested.
