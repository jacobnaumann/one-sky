## 06:10 UTC: First working build — globe, backend, app wired together
- **What:** Globe (`src/globe/`: custom day/night shader from real sun position, city lights, clouds, atmosphere, stars, people/echo/lantern/gaze points, wave arcs, threads, 24-part ring, bloom). Supabase project `evktxfawnualbbmoujip` with schema, RLS, rate-limited RPCs, pg_cron prune, 6 seeded welcome lanterns. Pure lib (`src/lib/`: sun, geo, tz table of 418 places, time, questions, moderation). Audio engine (`src/audio/engine.ts`). Network layer (`src/net/sky.ts`), UI (`index.html`, `src/styles.css`, `src/ui/`), orchestration (`src/main.ts`).
- **Why:** Core of the plan.
- **Decisions:** Backend, lib and audio were each built by a parallel helper agent to a written interface; I built the globe, UI and wiring. Column-level grants hide uids (clients must list columns, never `select *`). Hidden lanterns are announced by a `lantern_hidden` broadcast which the client confirms against the DB because public broadcasts can be spoofed. Place names sent by clients are screened server-side like lantern text. `world_totals` single-row table keeps thread/km totals cheap. Presence starts only after the visitor presses "Step into the sky".
- **Verified:** `npx tsc --noEmit` clean. `npx vitest run` 124/124. `node tests/db/rls.test.mjs` 83/83 against the live project (run by the backend helper). ## 07:40 UTC: Security review acted on; ripples, drift, sun news; hardened backend deployed
- **What:** Independent security review (no XSS/SQLi/secret leaks; real findings were spoofable realtime payloads, forgeable places/zones, table growth, report abuse, filter bypasses). Client: presence validated against the tz table and jitter box, only ids are read from broadcasts, `thread` broadcast removed (threads come only from the DB; ownership via `my_marks()`), per-sender rate limits, caps on arcs/echoes/announcements, hidden-lantern confirmation throttled, CSP meta tag, bidi/overflow containment, 3.5 s presence grace period. Database (`20261113050000_hardening.sql`): `places` table (418), server looks places up by tz and ignores client place text, zone computed server-side, max 3 zones per uid per day, lantern positions randomised server-side, tighter rate limits + global breakers in a `limits` table, pruning every 10 min, NFKC + invisible-character stripping in the text filter, email sign-up disabled. New features: ripple (ring of light around the Earth, broadcast), drift (tour of lanterns), sunrise/sunset feed lines, tap-anywhere local time, personal thread tally, sky strip on person cards, background-tab title notice, adaptive render quality, OG image, README, `scripts/reset-world.mjs`.
- **Why:** The review showed one hostile visitor could put arbitrary text in front of everyone and forge threads/zones; fixed before anyone is invited.
- **Decisions:** Not done on purpose: private realtime channel and captcha (documented under Known limits in [[architecture]]). Seven time zones can land one ring band away from the browser's own calculation because the server's tzdata is newer; accepted.
